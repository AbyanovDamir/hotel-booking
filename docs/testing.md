# Тестирование

Команда полного прогона:

```bash
mvn test
```

Последний полный прогон: **34 теста, 0 failures, 0 errors, BUILD SUCCESS**.

## Запуск тестов в контейнерах

```bash
chmod +x scripts/*.sh
./scripts/container-test.sh unit
```

Полный Linux-сценарий:

```bash
./scripts/container-test.sh all
```

Он выполняет 34 Maven-теста в `unit-tests`, поднимает две PostgreSQL и четыре
приложения, затем запускает `smoke-tests` из отдельного curl-контейнера. Только
сквозная проверка работающего стенда: `./scripts/container-test.sh smoke`.

Покрытые сценарии:

- загрузка Eureka context;
- сохранение/генерация `X-Request-Id` в Gateway;
- идемпотентный confirm/release, соседние интервалы и конфликт пересекающихся дат на реальной H2/JPA;
- защита от повторного `requestId` с изменёнными параметрами и освобождения чужого номера;
- однократное увеличение `timesBooked` при повторе запроса;
- порядок рекомендаций `timesBooked`, затем `id`;
- сага: `CONFIRMED`, ошибка → release + `CANCELLED`, повтор requestId и автоподбор;
- отмена бронирования, изоляция данных пользователей и отсутствие доступных номеров;
- регистрация, проверка пароля и формирование подписанного JWT с ролью и сроком жизни;
- внутренний ключ межсервисного API;
- MockMvc: успешные запросы, валидация, 400, 401 и 403.

Тесты используют AAA-структуру и `@DisplayName`; внешние сетевые сервисы в unit и
web-slice тестах заменены Mockito, а проверка блокировок работает с in-memory H2.
